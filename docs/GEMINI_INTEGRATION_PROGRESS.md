## build 66 実機安全試験

製品名を`InnerCorners GE`、Bundle IDを`local.prototype.InnerCorners.GE`へ確定し、build 66として`/Applications/InnerCorners GE.app`へ配置した。旧build 65は`/Applications/InnerCorners GE build65 backup.app`へ退避してあり、削除していない。

- macOSアクセシビリティ再許可後、Quartzイベントタップが1本・`enabled=true`になったことをOS側から確認。
- GE単独待機時の観測CPU使用率は0.0%。
- RC7を併起動すると、GE自身のイベントタップが1本から0本へ停止し、RC7側だけが1本を保持。
- RC7終了後、GEのイベントタップが0本から1本へ自動復帰。
- `⌃⌥⌘Q`をCGEventで送信すると、GEが終了。OSログにも緊急終了を記録。
- 非常終了が保存した`barrierEnabled=false`を、他設定を維持したまま`true`へ復元して再起動。イベントタップ1本への復帰を確認。
- ユーザー実機確認: 内部コーナーの低速・高速衝突、壁停止とアクション発火、再衝突キャンセル、Option緊急通過はいずれも異常なし。

自動確認部分はプロセス、Quartzイベントタップ一覧、OSログで確認した。カーソル操作を伴う項目はユーザーが実機で確認した。

## builds 67–69 ワークスペース表示キャンセル試験

- Mission Control、Application Windows、Show Desktop、Appsのうち、ある機能の表示中に別コーナーへ衝突した場合も、次の機能を重ねて起動せず直前の表示をキャンセルする状態管理を追加。

- build 68の高速なApps→Show Desktop操作で、Appsの非同期表示よりEscapeが先行し、遅れてApps検索画面だけが現れる競合を実機で確認。

## build 70 Apps起動通知の回帰試験

- build 69の組合せ試験ログで、高速なApps→別コーナーはキャンセルされる一方、Apps表示後に約3秒置いた操作ではApps自身のアプリ切替通知が待機状態を消すことを確認。
- `com.apple.apps.launcher`、旧OS用`com.apple.launchpad.launcher`、`com.apple.exposelauncher`、`com.apple.dock`だけを待機解除の例外とした。通常アプリへの切替と識別不能な通知は安全側で解除する。
- ユーザー実機試験で、Apps完全表示から約5秒後のShow Desktop衝突がキャンセルとして処理されることを確認。
- 続く高速試験では、Appsから約1.1〜1.4秒後のShow Desktop衝突を複数回キャンセルとして記録。意図しないApps／Spotlight表示の残留はユーザーから報告されなかった。
- Mission Control、Application Windows、Show Desktop、Appsについて、同一機能への再衝突と異なる機能間の全方向を実機操作とOSログで確認。いずれも次の機能を重ねて起動せず`workspace-cancel-requested`として処理された。
- build 70起動後のQuartzイベントタップは1本・`enabled=true`。
- build 70を`pmset sleepnow`で実スリープさせ、同一PIDで復帰。復帰直後は壁を停止した安全確認状態を維持し、5秒以上経過後にカーソルを画面中央へ移すと壁を再開した。再開後もイベントタップ1本・`enabled=true`で、復帰中の誤発火は記録されなかった。
- 3画面をL字配置へ変更する過程の複数通知すべてで安全待機へ入り、各回5秒以上経過後に壁を再開。変更後は画面1・2・3それぞれの内部コーナーを実機操作し、ログ上の進入元と対象画面が一致した。別画面の同座標角への取り違え、誤発火、クラッシュは記録されなかった。
- 一時停止中はQuartzイベントタップが0本となり、L字配置の3つの内部コーナーを自由に通過できた。一時停止解除後はイベントタップ1本・`enabled=true`へ戻り、壁停止、Mission Control発火、別コーナーでのキャンセル、再発火が正常に復帰した。

## build 71 除外アプリ試験

- Finderを除外し「アクションのみ」で試験。イベントタップ1本を維持し、壁は作動、アクションは抑制された。
- 抑制範囲を「バリアとアクション」へ変更した初回試験では、Finderウインドウ前面でも壁経路のApps発火を記録。保存設定自体は`com.apple.finder`・`barriersAndActions`で正しかった。
- 原因は、`didActivateApplicationNotification`が持つ正しいFinder情報を、切替直後の`NSWorkspace.frontmostApplication`再照会結果で上書きしていた競合と判断。通知のアプリ名・Bundle ID・PIDを優先するよう修正し、通知情報優先の回帰テストを追加。
- build 71で同じFinderウインドウ前面試験を再実施。3つの内部コーナーで壁・アクションとも抑制され、OSログにも発火は記録されなかった。Codexへ戻るとイベントタップ1本へ復帰。
- 試験後、Finderを除外一覧から削除し、抑制範囲を試験前の「アクションのみ」へ復元。保存データで除外一覧が空であることを確認した。
- フルスクリーン自動抑制を有効にし、抑制範囲を「壁とアクションの両方を一時停止」として実機試験。フルスクリーン中は内部コーナーを通過でき、アクションログは0件。通常画面へ戻るとイベントタップ1本・`enabled=true`へ復帰した。試験後は自動抑制をオフ、抑制範囲を「アクションのみ抑止（壁は維持）」へ復元し、保存データで確認した。
- GEプロセスを約3秒`SIGSTOP`し、その間に現在位置から1 ptだけ往復する合成マウス移動を送ってWindowServerのイベントタップタイムアウトを実機再現。同一PID・同一タップIDのまま`enabled=true`→`false`となり、再開後の次のマウス入力で`true`へ自動復旧した。復旧後は3画面で壁衝突、Application Windows、Mission Control、Show Desktop、同一・別コーナーのキャンセルが正常に作動した。合成入力用補助物は一時領域のみで、製品には含めていない。
- 壁の遮断モードをスピードバンプ、保持時間300 msとして3画面で実機試験。初期衝突で停止し、押し続けると通過し、通過直後に逆方向へ戻ると再び停止することを確認。発火と再衝突キャンセルも正常で、イベントタップ1本・`enabled=true`を維持した。試験後は「常時遮断（Optionキーでのみ通過）」へ復元し、保存データで確認した。
- 3画面からASMを物理切断し、2画面構成で約5秒の安全待機後に壁を再開。残る2画面のコーナー発火とキャンセルが正常で、切断画面IDへの誤発火なし。ASM再接続後も約5秒の安全待機を経て3画面へ戻り、ASM固有の右上・右下割当を復元した。
- ASMの論理解像度を1920×1080相当から3840×2160相当へ変更し、安全待機後に新座標で壁を再開。変更後のコーナー発火とキャンセルが正常で、元の1920×1080相当へ戻す過程の複数通知でも安全期限を更新し、最終座標で再開した。全過程で同一PIDを維持し、誤発火・クラッシュなし。
- Appsの非同期起動直後を狙った高速再衝突を反復。Apps→同じAppsは最短約0.64秒、Application Windows→Appsは約0.95秒、Apps→別機能は最短約1.10秒でキャンセルされ、意図しないApps／Spotlight画面の残留はなかった。競合原因だったApps起動完了前のキャンセルを1秒未満で確認済み。
- GUIの診断情報で、Apps起動要求後に「アプリ起動：非同期処理が完了しました」が複数回記録されることを確認。コーナーを一時的に「ディスプレイをスリープさせる」へ変更した試験では「システムコマンド：非同期処理が完了しました」に続き、画面スリープ前停止、復帰安全確認、画面内位置確認後の壁再開を記録した。試験後は全コーナーを`systemHotCorner`へ復元し、保存データで確認した。
- 復帰安全待機と一時停止を重ねる試験では、画面復帰から設定操作可能になるまでに安全確認が完了し、同時状態を作れなかったため順序を逆にして検証。一時停止中に画面配置を変更してもイベントタップ0本を維持し、途中再開・誤発火なし。一時停止解除後はイベントタップ1本へ戻り、変更後の座標でApps、Application Windows、キャンセルが正常に作動した。試験用配置はユーザーが元のL字へ復元した。
