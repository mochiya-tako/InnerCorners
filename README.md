# InnerCorners v0.11.0 RC6

macOSのマルチディスプレイ接合部に短いカーソル壁を作り、内側角でも標準ホットコーナーを使いやすくするメニューバーアプリの試作品です。画面・角ごとの矩形アクション機能も試作コードとして残していますが、現在の主機能は接合部ソフトバリアです。

## 試作品の範囲

- 各画面・各4隅への個別割当
- 10〜100 ptの反応範囲
- 0〜500 msの滞留時間
- 同じ領域から出るまで再発動しないラッチ
- アプリを有効にしなくても現在の画面・角判定を表示するライブ診断
- 実際の画面配置と8つの反応領域を示すプレビュー
- ウインドウやファイルのドラッグ中は発動を抑止
- アクセシビリティ権限の状態表示（要求はボタン操作時のみ）
- 権限不要のテスト音ボタンと、Application Windowsの対象になる前面アプリ表示
- macOS標準設定の割当を読み、Mission Control／アプリケーションウインドウ／デスクトップ／「アプリ」を実行
- v0.11.0 beta 1ではクイックメモ、通知センター、スクリーンセーバ開始、画面ロック、ディスプレイスリープの公開向け実行経路を追加（コンパイルおよび現行実機での発動・復帰確認済み）
- Shift／Control／Command付き標準ホットコーナーを判定し、必要キーが押されている場合だけ発動。Optionは緊急通過を優先
- 画面構成変更通知への追従
- ColorSyncの画面UUIDによる設定保持
- 接合部の角を挟む方向別ソフトバリア（長さ10〜100 pt）
- 高速移動時は境界交差点に加え、移動先も使ってすり抜けを抑止
- 壁に当たった場合だけ境界の手前0.5 ptへカーソルを補正
- 壁への最初の衝突だけを発火点にし、同じ角の壁は常時維持したままアクションの連続発火だけを抑制
- 同じ物理接合点を共有する左右の角をまとめて抑制し、反応範囲を出た後に再作動可能
- 常時壁でもOptionキーを押しながら移動すれば即時通過できる緊急解除
- 独自領域アクションもOption押下中は抑止。画面スリープと実際のディスプレイ構成変更後は、5秒経過かつ全領域外への移動を確認してから再開
- スリープ復帰・画面構成変更後は、5秒経過かつ接合部から離れた画面内位置を確認するまで壁を再作動しない
- アプリ自身はログイン項目を勝手に変更しない（安全確認のため現在はログイン項目から削除済み）
- Dockと⌘Tabへ常時表示し、前面へ切り替えて⌘Qで終了可能
- カーソル監視とは独立した⌃⌥⌘Qを登録し、壁設定をオフで保存してから緊急終了
- 提供された`ic_icon.png`から16〜1024pxを収録したICNSを生成し、Dock／Finderのアプリアイコンとして使用
- メニューバー画像は画像カタログ名ではなく、同梱したRetina PNGを直接読み込み、18ptで表示（v0.8.6で実機ログ上の読み込み失敗を修正）
- 提供された`ic_menu_icon.png`の透明余白を自動除去し、18px／36pxのメニューバー画像として使用

矩形アクションの検出は、有効時または設定画面を開いている間だけ、50 Hzのタイマーから`NSEvent.mouseLocation`を読みます。ソフトバリアはアクティブなセッションイベントタップと`CGWarpMouseCursorPosition`を併用するため、アクセシビリティ権限が必要です。権限要求は設定画面のボタン、または検証用起動引数を明示した場合だけ行います。

## ビルド

完全版Xcodeを選択した環境では、通常は次でビルド・テストできます。

```sh
swift test
swift build -c release
```

この作業環境ではCommand Line ToolsのSwiftPMライブラリにビルド番号の不整合があったため、アプリ本体は`swiftc`で直接コンパイルしてあります。ソースの最低対象はmacOS 14です。

同梱の`Scripts/build_app.sh`を実行すると、arm64アプリのコンパイル、アドホック署名、署名検証、ZIP作成まで再現できます。

通常起動では権限要求を出しません。検証時に同じアプリ本体からアクセシビリティ要求を出す場合だけ、実行ファイルへ`--request-accessibility`を渡します。

設定GUIは実際の2画面それぞれに4隅の割当欄が表示され、選択変更が反映されるところまで確認済みです。滞留時間、領域外へ出るまでのラッチ、別領域への直接移動、方向別バリアの生成と高速移動時の補正は自動検査済みです。ただし、これはまだ恒久導入用の完成版ではありません。

通常版を起動した状態の過去の一時測定ではCPU約0.3%、常駐メモリ約31 MBでした。v0.10.3では、独自領域アクション無効・設定画面を閉じた待機状態の5秒間サンプルが全回CPU 0.0%かつsleepingでした。いずれも長時間測定ではありません。

権限不要のテスト音は実GUIから実行し、状態表示まで更新されることを確認済みです。Mission Control等の合成キー送信は実機で作動しなかったため、v0.6.2では壁への衝突時に現在のDockホットコーナー設定を読み、Apple純正システムアプリをLaunchServices経由で起動します。
